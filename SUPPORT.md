## Comment se déroule une adhésion

L'adhésion ne repose sur aucun examen préalable. Elle se déroule en quatre étapes,
automatiquement.

### 1. Ouverture de la demande

La demande se fait par le
[modèle « Demande d'adhésion »](https://github.com/ENUN-ORG/.github/issues/new/choose?template=rejoindre-enun.md),
dans le dépôt [.github](https://github.com/ENUN-ORG/.github/issues).

Le modèle applique automatiquement l'étiquette `adhesion` et le préfixe de titre
`[ADHÉSION]`. Ce sont ces deux marqueurs, et non le texte saisi, qui déclenchent
l'automatisation.

### 2. Identification de la personne

**Votre identité n'est pas lue dans le formulaire.** Elle est fournie par GitHub
lui-même, qui rattache chaque issue à son auteur. L'invitation est donc adressée au
compte qui a ouvert la demande.

Il en découle que le formulaire ne comporte aucun champ d'identifiant : il est
impossible de demander l'adhésion pour le compte d'un tiers.

### 3. Envoi de l'invitation

L'automatisation crée une invitation et commente la demande, puis la clôture.

L'invitation est transmise par GitHub, qui la notifie de deux façons :

- dans vos **notifications GitHub** (icône de cloche) ;
- par **courriel**, à l'adresse associée à votre compte GitHub.

C'est pourquoi le formulaire demande l'adresse e-mail **de votre compte GitHub** et
non votre adresse professionnelle. Si votre compte n'a pas d'adresse e-mail
principale, le courriel peut ne pas aboutir : l'invitation reste alors accessible
une fois connecté à GitHub.

### 4. Acceptation

L'adhésion n'est définitive qu'après acceptation de votre part. Une invitation non
acceptée ne confère aucun droit.

1. Ouvrez [la page d'invitation](https://github.com/orgs/ENUN-ORG/invitation).
2. Cliquez sur **Accept invitation**.

L'acceptation est le seul moment où l'automatisation peut vous inscrire dans l'équipe
`membres`. Elle intervient immédiatement après votre clic.

### Délai

Les quatre étapes sont immédiates. Si l'invitation n'apparaît pas, vérifiez les
notifications et les courriers indésirables du compte concerné, puis
[la page d'invitation](https://github.com/orgs/ENUN-ORG/invitation).

### Demande d'accès `moderateur`

L'accès `moderateur` se demande dans le même formulaire mais n'est **pas** accordé
automatiquement. Il se décide au regard des contributions déjà livrées.

## Avant d'ouvrir une issue

La documentation du dépôt concerné répond généralement à la question. À défaut,
l'onglet **Issues** du dépôt peut déjà contenir une réponse : le sujet a peut-être
déjà été traité.

Si une issue doit être ouverte, précisez :

1. l'objectif recherché
2. les démarches déjà entreprises
3. le résultat obtenu, avec le message d'erreur complet le cas échéant
4. l'environnement : système, versions des outils et de l'application

Une description précise accélère nettement le traitement.

## Propositions

Les idées d'amélioration et les propositions de nouveaux modules sont attendues, y
compris à l'état d'ébauche. Utilisez le
[formulaire de proposition](https://github.com/ENUN-ORG/.github/issues/new/choose?template=proposition.yml) :
il structure la demande et rend la discussion possible avec le reste de l'équipe.

## Hors sujet

Cet espace couvre les dépôts de l'organisation. Les demandes sans rapport avec un
projet de l'écosystème, et les demandes de documents ou de services universitaires,
relèvent des services des universités et non de cette organisation.
